# EQ Band Monitor · 游戏音频频谱监视与 EQ 判断交接

监听电脑正在播放的声音，**把游戏里各场景的原始音频录下来**，附上一份已算好的
结构化报告，交给 AI（或你自己）判断该怎么调 EQ。

面向的是这类问题：*「FPS 里听不清脚步，但不敢乱抬 EQ，怕枪声炸耳」*。
比起给一个"万能参数"，这个工具把**可复核的事实**算清楚，让判断有据可依。

| 做 | 不做 |
|---|---|
| 录下**原始 PCM**（系统回环，绕过一切 EQ / 压缩） | 不替你决定 EQ 该调成什么样 |
| 计算确定性事实（电平 / 61 段频谱 / 瞬态 / 音调性） | 不做审美判断 |
| 打包成 `report.md` + `report.json` + `audio/` | 不隐藏中间数据 |
| 读写 FxSound `.fac` 预设（字节级往返） | 不注入、不 hook、不读游戏内存 |

## 界面

全 Qt（PySide6）实现，没有 Web 视图、没有额外 UI 框架：

- **悬浮窗**：61 段实时频谱，置顶、**点击穿透**、不抢焦点、不进 Alt+Tab
- **托盘**：切设备 / 载入基线预设 / 开始录制 / 关于
- **交接包窗口**：录制概览 + 完整报告 + 一键复制
- **全局热键**：Win32 `RegisterHotKey` + Qt 原生事件过滤器

## 录制流程

场景是**两个维度**的组合：**位置 × 移动方式**。

| 维度 | 取值 | 怎么选 |
|---|---|---|
| 位置 | 自己 / 楼下 / 旁边 / 远处 | `F2` / `F3` / `F4` / `F5` |
| 移动方式 | 静步 / 正常走 / 奔跑 | `Ctrl+Shift+1` / `2` / `3` |

共 4×3 = 12 种组合。热键不够给每种组合配一个，所以先用 `Ctrl+Shift+1/2/3`
选当前移动方式（悬浮窗左下角有徽标 `[静步]`），再按位置键录制。
录出来的场景名会是「楼下脚步·静步」这样。

游戏中（**必须无边框窗口 / 窗口化全屏**，独占全屏会盖住悬浮窗）：

| 按键 | 场景 | 做什么 |
|---|---|---|
| `Ctrl+Shift+1` | 移动方式 = 静步 | 切换徽标，之后 F2–F5 都按静步录 |
| `Ctrl+Shift+2` | 移动方式 = 正常走 | 默认值 |
| `Ctrl+Shift+3` | 移动方式 = 奔跑 | |
| `F1` | 静止底噪 | 站安全区不动 3 秒 |
| `F2` | 自己脚步 | 自己按当前方式移动 3 秒（**干扰源**，会盖住敌人） |
| `F3` | 楼下脚步 | 楼上/楼下敌人正在按当前方式移动时录 3 秒 |
| `F4` | 旁边脚步 | 近处敌人在移动时录 3 秒 |
| `F5` | 远处脚步 | 较远敌人在移动时录 3 秒 |
| `F6` | 跳跃/落地 | 起跳与落地 |
| `F7` | 开火 | 打一梭子 3 秒 |
| `F8` | 手榴弹 | 破片手雷爆炸 |
| `F9` | 震撼弹 | 闪光/震撼弹爆响 |
| `F10` | — | **生成交接包** |

每按一次开始，再按同一个键结束。

**楼下和远处建议三种方式都录。** 同一个楼下，静步下楼和奔跑下楼的低频/中高频
分布差别很大；只录一种不能代表该位置的全部情况。报告开头会打印覆盖矩阵，
并列出还缺哪些组合。

### 完整快捷键

| 键 | 功能 |
|---|---|
| `F1`–`F9` | 录制各场景（再按同一键结束） |
| `Ctrl+Shift+1` / `2` / `3` | 移动方式：静步 / 正常走 / 奔跑 |
| `F10` | 分析已录音频，生成交接包 |
| `F11` | 清空录制记录（磁盘 WAV 保留） |
| `Ctrl+Shift+R` | 峰值保持清零 |
| `Ctrl+Shift+D` | 切换显示范围（60/45/90 dB） |
| `Ctrl+Shift+H` | 隐藏 / 显示悬浮窗 |
| `Ctrl+Shift+Q` | 退出 |

## 为什么「自己脚步」是干扰而不是目标

1. **它和敌人脚步在频谱上高度重叠。** EQ 只能整体加权某段频率，
   无法区分「这是谁的脚步」。
2. **抬脚步频段会同时放大自己的脚步**，反而更难听见敌人。

所以 `F2` 标为 `mask`（干扰源），报告里单独输出一节
「自己脚步 vs 敌人脚步：能否分开」—— 差异不足 6dB 时会明确说明
**EQ 无法解决**，需要从游戏内设置或听音习惯入手。

## report.md 里有什么

1. **录制文件总览** —— 每个文件的时长/峰值/RMS/噪声底
2. **位置 × 移动方式 覆盖矩阵** —— ✔/✗ 标出还缺哪些组合
3. **数据质量警告** —— 削波、静音、样本不足（放前面，避免基于坏数据下结论）
4. **各场景明细** —— 起音事件数、活跃占比、起音时间、音调性、声道相关
5. **分场景频谱** —— 61 段 1/6 倍频程（19.7Hz–20.2kHz）
6. **场景间形状差异** —— 已去除整体音量，直接指出最该提升/衰减的频段
7. **信噪比** —— 想听清的声音相对底噪的富余
8. **距离衰减分析** —— 旁边/楼下/远处的 4kHz 以上相对倾斜
9. **自己脚步 vs 敌人脚步** —— 能否用 EQ 分开
10. **移动方式差异** —— 每个位置各自展开静步/正常/奔跑；再横向对比同一方式在不同位置
11. **当前基线预设** —— 你的 `.fac` 内容（若已加载）
12. **分析约定** —— dBFS 定义、场景语义、EQ 可调范围

关键：**频谱值与 EQ 增益 1:1 对应**。EQ 在某段抬 +6dB，该段读数就 +6dB
（实测偏差 0.02dB）。所以报告里的差值可以直接当增益用。

## 产物在哪

```
%USERPROFILE%\Documents\EQBandMonitor\recordings\
    MMDD_HHMMSS_below-run.wav     原始音频（24-bit PCM，立体声，未处理）
    MMDD_HHMMSS_fire.wav
    ...
    handoff_MMDD_HHMMSS\
        audio\  *.wav             音频副本
        report.md                 ← 把这个交给 AI
        report.json               同一份数据的机器可读版
```

> 文件名里**不能有冒号**：NTFS 会把 `x_below:run.wav` 当成「文件 `x_below`
> 的备用数据流 `run.wav`」，目录里只剩 0 字节文件。所以组合键落盘时冒号换成
> `-`，而 `report.json` 的 `key` 字段仍保留原始 `位置:方式`。

运行日志：`%LOCALAPPDATA%\EQBandMonitor\app.log`

## 技术要点

### 三级多分辨率 FFT

20Hz 处 1/6 倍频程带宽只有 2.3Hz，4096 点窗（bin 宽 11.7Hz）分辨不出：

| 频段 | 窗长 | bin 宽 |
|---|---|---|
| 19.7–111 Hz | 65536 | 0.73 Hz |
| 125–445 Hz | 16384 | 2.93 Hz |
| 500–20.2 kHz | 4096 | 11.7 Hz |

实测峰值精度：25Hz 误差 0.19%，30Hz 误差 0.05%，1kHz 误差 0.13%。

### 为什么不用粉噪补偿

1/3–1/6 倍频程带已经对粉噪近似平坦，再加补偿反而破坏
「带内 dB ↔ EQ 增益」的 1:1 对应关系。

### 噪声底必须排除数字静音

WASAPI loopback 在没有音频流经过时输出**精确的 0.0**。
直接取分位数会得到 -180dB 这种假值，所以统计时排除数字静音帧并单独报告其占比。

### 24-bit 而非 16-bit

16-bit 在 -60dB 以下量化噪声会吃掉底噪信息，而我们要分析底噪。

## 自测

```powershell
python selftest.py          # 分析器（34 项）
python selftest_suggest.py  # .fac / 自由拟合 / 建议引擎 / 组合键（46 项）
python selftest_raw.py      # 原始音频 → WAV → 分析 → 交接包（58 项）
python selftest_overlay.py  # 悬浮窗页脚 / 移动方式徽标（7 项）
```

`selftest_overlay.py` 用离屏渲染验证 —— 分层透明窗口截屏得到的是纯黑，
所以让 Qt 把 Overlay 画到 QImage 上再比像素，测的是同一份 `paintEvent`。

`.fac` 往返测试是**字节级**的：导出文件与原始文件逐字节一致。

## 测量点

程序默认自动挑一个**有信号**的 loopback 端点。

若系统默认输出是 `FxSound Speakers`（虚拟增强器），从它采集通常是**正确**的：
游戏把音频渲染给 FxSound，这里 loopback 拿到的是 **FxSound 处理之前**的原始信号。

选错了用托盘菜单 →「输出设备」手动指定。

## 安全说明

本软件**不注入进程、不 hook 游戏、不读游戏内存**，只用标准 Win32 顶窗 +
`RegisterHotKey`，也不产生任何声音输出。
