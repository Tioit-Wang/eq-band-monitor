# EQ 频段监视器（EQ Band Monitor）需求规划 v1

> 目标平台：Windows 11（本机已验证 10.0.26200 / AMD RX 6750 GRE / HECATE G3 Max 输出端点）
> 文档状态：待确认（文末有 5 个必须拍板的决策点）

---

## 1. 场景与目标

### 1.1 使用场景
在 FPS 游戏中反复做两件事：

1. **走动 / 绕后** → 听到脚步声；
2. **开枪 / 交火** → 听到枪声与爆炸声。

同时打开一个 10 点参数均衡器（截图界面：频点 / 增益 dB / Q 值，横轴 20Hz–20kHz 对数，纵轴 ±12dB），
希望通过调整 EQ 达成：**脚步更突出、枪声更不刺耳**，从而提升信息获取效率。

### 1.2 真正要解决的问题
当前痛点不是"看不见频谱"，而是：

> 我不知道**脚步声的能量集中在哪几个频点**，也不知道**枪声的能量集中在哪几个频点**，
> 因此无法判断 EQ 上哪个点该抬、哪个点该砍、抬多少。

所以本软件的核心不是"通用频谱仪"，而是 **A/B 场景能量对比 + 可直接翻译成 EQ 操作的结论**。

### 1.3 成功标准（一句话）
用户在看到软件输出的 30 秒内，能明确说出："把 500Hz 抬 +4dB，把 4kHz 砍 −5dB"，并且敢按下应用按钮。

## 3. 功能需求

按 P0（MVP 必须有）/ P1（第一版应做）/ P2（后续增强）分级。

### F1 音频采集（P0）

- **F1.1** 通过 WASAPI loopback 采集**指定输出端点**的系统混音（不是麦克风）。
- **F1.2** 设备选择列表（托盘菜单），显示友好名 + 是否为当前默认设备。
- **F1.3** 启动时默认跟随"系统默认输出设备"；默认设备切换时自动跟随（可关）。
- **F1.4** 设备热插拔 / 被拔出时自动重连，悬浮窗显示 `设备断开，重连中…`。
- **F1.5** 采样率自适应（44.1k / 48k / 96k 均支持），内部统一重采样到 48kHz。
- **F1.6** 静音 / 无信号检测：连续无信号时显示"无信号"，不刷假数据。
- **F1.7** 通道模式：`合并(mono)` 默认；`L/R 分开`（P1）；`Mid/Side`（P2）。

### F2 频谱分析（P0）

- **F2.1** FFT 窗长可配：2048 / 4096（默认）/ 8192，50% 重叠，Hann 窗。
- **F2.2** 频带聚合：默认 **1/3 倍频程，20Hz–20kHz 共 29 段**（中心频率 25 / 31.5 / 40 / 50 / 63 / 80 / 100 / 125 / 160 / 200 / 250 / 315 / 400 / 500 / 630 / 800 / 1k / 1.25k / 1.6k / 2k / 2.5k / 3.15k / 4k / 5k / 6.3k / 8k / 10k / 12.5k / 16k）。
- **F2.3** 显示刻度：dBFS，范围可配（默认 −90…0 dB，跨度 60dB 可调）。
- **F2.4** 三种显示模式（可切换）：
  - `Raw`：原始能量；
  - `粉噪补偿（默认）`：按 +3dB/倍频程 补偿，使粉噪/游戏底噪显示为平直，便于肉眼比较；
  - `A 加权`：模拟人耳响度感知，更接近"听起来多大声"。
- **F2.5** 时间平滑：满足 attack 10ms / release 200ms 的峰值包络，避免抖动。
- **F2.6** 峰值保持（peak hold）：每段显示峰值，可一键清零，保持时间可配（默认 2s 淡出）。

### F3 频段数值输出（P0）— 用户原始需求"输出每个频段的大小"

- **F3.1** 悬浮窗内以柱状图 + 每段 dB 数值显示当前能量。
- **F3.2** 主读数区显示 **Top-5 能量最强频段**（频率 + dB），实时刷新。
- **F3.3** "精确峰值频点"读数：对最强谱峰做抛物线插值，给出 **1Hz 精度**的中心频率（例：`峰值 412 Hz`）。← 这直接对应 EQ 上的"频点"输入框。
- **F3.4** 鼠标悬停某段时显示该段 tooltip 数值（悬浮窗穿透模式下的可选项，P2）。
- **F3.5** 数值刷新率可配 15 / 30 / 60 fps（默认 30）。

### F4 A/B 场景快照对比（P0，**核心差异化功能**）

单纯看实时频谱无法用于调 EQ（人眼跟不上且瞬时值不可信），必须用**统计快照对比**。

- **F4.1 采集快照**：全局快捷键触发，默认采集 3.0 秒（可配 1–10s），期间悬浮窗显示倒计时与进度。
  - `F8` → 采集 **快照 A（脚步 / 目标声音）**
  - `F9` → 采集 **快照 B（枪声 / 干扰声音）**
- **F4.2 统计量**：每段同时保存 `均值`、`中位数`、`P95`（瞬态声用 P95 更准）、`最大值`。默认结论用 P95，可切换。
- **F4.3 归一化开关（默认开）**：按总能量把 A、B 拉到同一响度，否则结论会退化为"枪声更响"。归一化后比较的是**频谱形状差异**。
- **F4.4 差值视图**：横向条形图显示 `B − A`（dB）。
  - 正值（红）＝ 该频段枪声占优 → **建议砍**
  - 负值（青）＝ 该频段脚步占优 → **建议抬**
- **F4.5 自动结论文本**：如"脚步在 315–800Hz 领先 8.4dB；枪声在 3.2–5kHz 领先 11.2dB。"
- **F4.6 EQ 建议表**：输出与用户 EQ 节点对齐的 10 组建议（频点 / 建议增益 delta / 说明），限制在 ±12dB 内。
- **F4.7 多次采样可累加**（对 A 或 B 重复快捷键，取平均），并可"清除快照"。

### F5 实时 / 快照视图切换（P1）

- 顶部两个 tab：`实时` / `对比`。对比视图下同时画出 A、B 两条平滑曲线 + 差值柱。

### F6 EQ 曲线叠加（P1）

- **F6.1** 用户手动录入当前 EQ 的 10 个节点：`频点 Hz` / `增益 dB` / `Q`（与截图界面字段一一对应）。
- **F6.2** 按 biquad（peaking EQ）级联计算幅频响应，作为半透明曲线叠加在频谱上。
- **F6.3** "有效频谱"预览：把测得的 B 曲线减去 EQ 响应，直观看到"砍完 4kHz 之后还剩多少"。
- **F6.4** 预设保存/切换（不同游戏不同 EQ），JSON 落盘。

### F7 校准（P1）

- **F7.1** 底噪校准：静音 3 秒采样，得到各段噪声底，之后显示可减去噪声底（`显示 = 10log10(10^(实测/10) − 10^(噪声/10))`）。
- **F7.2** 电平校准：可选输入参考信号（如 −20dBFS 粉噪），校正显示偏置。
- **F7.3** 一键恢复默认校准。

### F8 数据记录与导出（P2）

- **F8.1** 快照可导出 CSV（列：频段中心频率、A 均值/P95、B 均值/P95、差值）。
- **F8.2** 可选连续录制频谱历史（默认关，占空间）。
- **F8.3** 截图当前悬浮窗（含时间戳）用于对比记录。

### F9 设置（P0/P1 混合）

P0：设备、窗长、显示范围、刷新率、快捷键、平滑参数、粉噪补偿开关。
P1：EQ 节点编辑、预设、开机自启、缩放、位置锁定、主题（深色/浅色）、导出。

所有配置存 `%APPDATA%\EqBandMonitor\config.json`。

## 5. 技术方案

### 5.1 技术栈（已在本机验证）
| 层 | 选型 | 验证状态 |
|---|---|---|
| 音频采集 | `soundcard`（WASAPI loopback） | ✅ 实测可枚举 5 个 loopback 端点，实际开流 20 block 全部取到数据 |
| 数字处理 | `numpy` 2.2.4 + `scipy` 1.16.2（重采样/滤波） | ✅ 已安装 |
| GUI | PySide6（Qt6）自定义 QPainter 绘制 | 需 `pip install PySide6` |
| 打包 | PyInstaller onedir | 待做 |
| 备选 | `sounddevice`（PortAudio WASAPI）或 ctypes 直调 IAudioClient，若 loopback 在特定机器失败 | 备选 |

> 为何不用 matplotlib：其重绘开销 30–100ms，无法 60fps；用 QPainter 每帧只画 29 个矩形 + 1 条路径，成本 < 1ms。
> 为何不用 .NET/WPF：本机**无 .NET SDK**，且 Python 方案已验证可行。

### 5.2 进程与线程模型
```
[采集线程] soundcard recorder → ring buffer(48k, stereo, 4096) 
      → [分析线程] 加窗 → rfft → 功率谱 → 1/3 倍频程聚合 → 平滑包络 → 快照累加
      → [UI 线程 30/60fps] QTimer → 读最新帧 → QPainter 绘制悬浮窗
[热键线程] RegisterHotKey 消息循环 → 触发快照 / 隐藏
```
采集与分析独立于 UI，UI 卡顿不丢音频；`ring buffer` 用 `collections.deque` + numpy 预分配。

### 5.3 算法细节
- 窗函数 Hann；`rfft` 长度 = 窗长；功率谱 `|X|² / (Σw²)`；功率谱密度按带宽折算为带内能量。
- 1/3 倍频程带聚合：带边 `fc·2^(±1/6)`，带内功率求和（不是取最大，避免窄峰误判）。
- 时间平滑：`env = max(inst, env·decay)`，`decay = exp(-Δt/τ)`，τ_release = 200ms；上升立即跟随。
- 峰值频点：在最强带内对谱线做 3 点抛物线插值 → `f_peak = (k + 0.5·(a−c)/(a−2b+c))·Δf`。
- 粉噪补偿：每段加 `+3·log2(fc/1000)` dB。
- EQ 响应：标准 peaking biquad（RBJ cookbook），级联 10 段，取 `20log10|H|`，在 20Hz–20kHz 对数栅格上算 512 点。

### 5.4 与用户 EQ 的映射
用户 EQ 的 10 个可调节点 ≈ 25 / 63 / 125 / 250 / 500 / 1k / 2k / 4k / 8k / 16k（与截图节点位置一致）。
软件的"建议表"直接输出这 10 行的目标增益，用户逐行照抄即可。

### 5.5 悬浮窗布局草图

│ ● EQ Band Monitor      [实时|对比]  ⚙ ─ ✕   │  顶栏(20px)

├──────────────────────────────────────────────┤
│ PEAK  412 Hz   ▏TOP5: 500Hz -28.4  1k -31.2… │  读数区(26px)
├──────────────────────────────────────────────┤

## 6. 界面与交互细节

- 悬浮窗颜色：深色底 `#0d1117`，柱体青蓝渐变（呼应截图 EQ 的高亮色 `#22d3ee`），峰值线白。

## 8. 验收标准

1. 播放一段游戏录像音频，悬浮窗 29 段全部有读数，数值随声音变化，峰值频率读数误差 < 5%。
2. 在游戏中（无边框窗口模式）悬浮窗稳定可见，**点击其位置游戏仍能正常操作**（NFR-3）。
3. 连续运行 30 分钟，CPU < 5%、内存无持续增长。
4. 按 `F8` 走 3 秒、按 `F9` 开 3 秒，30 秒内得到"哪几个频段该抬、该砍、多少 dB"的明确结论。
5. 拔插耳机 3 次，程序自动恢复采集，不崩溃。
6. 关闭程序后系统音频无任何残留改动（本软件不参与音频链路）。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 独占全屏下悬浮窗不可见 | 功能失效 | 文档要求用无边框窗口；M1 就验证 |
| 游戏反作弊把置顶窗判为可疑 | 可能封号误判 | 纯标准窗口，无注入/无 hook；不读进程；提供"已知风险"提示 |
| loopback 采到的是 EQ 后信号 | 读数随 EQ 变化，绝对电平不准 | 归一化对比为主；文档标注测量点；可选"采集前 EQ 归零"流程 |
| 个别声卡 WASAPI loopback 初始化失败 | 无数据 | 备选 `sounddevice` / 直调 IAudioClient，做设备自检页 |
| 快捷键与游戏冲突 | 无法触发快照 | 全部可改，并支持托盘点击触发 |
| Python 打包体积 ~80MB | 略大 | onedir + 排除无关模块；或后续 Rust 重写（性能非瓶颈，暂不做） |
